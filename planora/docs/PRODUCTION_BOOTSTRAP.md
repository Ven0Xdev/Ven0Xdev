# אתחול מנהל־העל הראשון בייצור

המסמך הזה הוא הנוהל המלא ליצירת חשבון ה-SUPER_ADMIN הראשון של OVIAX בסביבת
הייצור. הוא נכתב כדי שאפשר יהיה לבצע אותו פעם אחת, בבטחה, בלי להדביק סודות
לשום מקום מלבד הסביבה עצמה.

## מה נבנה כאן

- **פקודת שרת**, לא נתיב HTTP. אין `/api/bootstrap` ואין כפתור בממשק. מה שאין
  לו כתובת אי אפשר לתקוף מהאינטרנט.
- **חד־פעמיות אמיתית**. שורת `AdminBootstrap` עם מפתח ייחודי אחד (`lock`)
  היא המנעול, ולכן גם שתי הרצות במקביל לא ייצרו שני מנהלי־על.
- **SUPER_ADMIN אינו ניתן להענקה** דרך האפליקציה — בשום מסך, בשום פעולת שרת,
  בשום תפקיד. ראו `src/lib/auth/role-assignment.ts`.
- **אותו מנגנון סיסמאות של הייצור**: bcrypt, השדה `User.passwordHash`, ואותה
  השוואה שמבצע ספק ההתחברות `password` ב-`src/auth.ts`. אין מערכת סיסמאות שנייה.

## 1. משתני הסביבה הדרושים

| משתנה | תפקיד |
| --- | --- |
| `DATABASE_URL` | מחרוזת החיבור לייצור (Neon) |
| `SUPER_ADMIN_EMAIL` | הדואר האלקטרוני שאיתו תתחברו |
| `SUPER_ADMIN_NAME` | השם המלא שיוצג במערכת |
| `SUPER_ADMIN_PASSWORD` | סיסמה חזקה — 12 תווים לפחות, שלושה סוגי תווים |
| `SUPER_ADMIN_BOOTSTRAP_SECRET` | סוד אקראי — 32 תווים לפחות, בלי רווחים |

יצירת הסוד:

```bash
openssl rand -base64 48
```

הסוד אינו נשמר במסד הנתונים. נשמרת ממנו רק טביעת אצבע SHA-256, כדי שאפשר יהיה
להוכיח בדיעבד באיזה סוד נעשה שימוש בלי שהסוד עצמו יהיה ניתן לשחזור.

**ודאו ש-`DEMO_LOGIN_ENABLED` אינו `true` בייצור.** הפקודה מסרבת לרוץ אם הוא
פעיל.

## 2. איפה מוסיפים אותם ב-Vercel

Vercel → הפרויקט → **Settings** → **Environment Variables** → **Add New**.

לכל אחד מארבעת המשתנים:

- **Key / Value** — השם והערך
- **Environments** — סמנו **Production** בלבד
- **Sensitive** — סמנו. כך הערך אינו ניתן לקריאה חזרה מהממשק.

אל תסמנו Preview או Development. אל תוסיפו קידומת `NEXT_PUBLIC_` לאף אחד מהם —
קידומת כזו מזריקה את הערך לחבילת הדפדפן.

`DATABASE_URL` כבר קיים אצלכם מההתקנה.

## 3. האם ההגירות חייבות לרוץ קודם — כן

טבלת `AdminBootstrap` נוצרת בהגירה. בלעדיה אין מנעול ואין רישום ביקורת, ולכן
הפקודה בודקת זאת בעצמה ומסרבת לרוץ אם חסרות הגירות.

הריצו קודם, מול מסד הייצור:

```bash
npx prisma migrate deploy
```

הפקודה הזו מוסיפה בלבד. ההגירה `20260922160000_admin_bootstrap_audit` אינה
מוחקת טבלאות, עמודות או נתונים.

## 4. הפקודה עצמה

מהמחשב שלכם, מול מסד הייצור. משיכת המשתנים מ-Vercel:

```bash
vercel env pull .env.production.local
```

ואז, בתיקיית `planora/`:

```bash
env $(grep -v '^#' .env.production.local | xargs) npm run bootstrap:superadmin
```

או, בלי קובץ, עם הזנה ישירה לסביבת התהליך בלבד:

```bash
DATABASE_URL='…' \
SUPER_ADMIN_EMAIL='…' \
SUPER_ADMIN_NAME='…' \
SUPER_ADMIN_PASSWORD='…' \
SUPER_ADMIN_BOOTSTRAP_SECRET='…' \
npm run bootstrap:superadmin
```

> בשורת פקודה: רווח אחד בתחילת השורה מונע מרוב ה-shell-ים לשמור אותה
> בהיסטוריה. מחקו את `.env.production.local` מיד אחרי ההרצה.

פלט מוצלח מציג את מזהה המשתמש, הדואר, התפקיד ומועד היצירה — ולעולם לא את
הסיסמה או הסוד.

## 5. איך מוודאים שמנהל־העל נוצר

```bash
DATABASE_URL='…' npm run bootstrap:verify
```

הפקודה קוראת בלבד ומדווחת על חמישה דברים: מצב ההגירות, מנהלי־העל הקיימים,
מצב מנעול האתחול, הדגל `DEMO_LOGIN_ENABLED`, וחשבונות הדגמה עם סיסמה.

## 6. איך מוודאים שהאתחול נעול

אותה פקודה מדפיסה `מנגנון האתחול: נעול` יחד עם תחילת טביעת האצבע של הסוד.
בדיקה נוספת: הריצו את פקודת האתחול שוב. היא תסיים בהצלחה עם ההודעה
"האתחול כבר בוצע", בלי לשנות דבר.

גם בממשק: `/admin` מציג את מועד האתחול ואת הדואר שאותחל.

**לאחר אימות — הסירו מ-Vercel את ארבעת המשתנים** `SUPER_ADMIN_*`. הם אינם
נחוצים לאפליקציה, שאינה קוראת אותם כלל.

## 7. כניסה

1. דף ההתחברות של OVIAX בייצור
2. טופס **דואר אלקטרוני וסיסמה** — אותו טופס של כל המשתמשים
3. הדואר והסיסמה שהגדרתם

אחרי ההתחברות מנהל־העל מנותב ל-`/admin` — אזור ניהול הפלטפורמה: ארגונים,
פרויקטים, דירות, משתמשים ותפקידים. כל תפקיד אחר מנותב לאזור שלו, ואזור
הניהול מוחזר לו כ-404.

## מה הפקודה מסרבת לעשות

| מצב | התנהגות |
| --- | --- |
| כבר קיים SUPER_ADMIN | יציאה נקייה, "SUPER_ADMIN already exists", אפס שינויים |
| האתחול כבר בוצע | יציאה נקייה, "האתחול כבר בוצע", אפס שינויים |
| חסרות הגירות | שגיאה, ומפנה ל-`prisma migrate deploy` |
| `DEMO_LOGIN_ENABLED=true` | שגיאה |
| סוד או סיסמה חלשים | שגיאה עם פירוט מה חסר |
| הדואר כבר שייך למשתמש קיים | שגיאה — חשבון קיים אינו מועלה לדרגת מנהל־על |

## חשבונות הדגמה

סקריפטי ה-seed יוצרים משתמשים עם סיסמה ידועה, ולכן הם חסומים מלרוץ מול מסד
מרוחק או כאשר `NODE_ENV=production` — ראו `src/lib/admin/seed-guard.ts`.
`npm run bootstrap:verify` מדווח אם בכל זאת קיימים חשבונות כאלה בייצור.
